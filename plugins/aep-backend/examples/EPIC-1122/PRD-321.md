## Problem Statement

Customers must re-enter card details on every checkout. 34% of customers who reach the
payment step abandon the transaction (checkout funnel, Q2 2024, ID market). This PRD
specifies the `POST /payment/v1/cards` endpoint to save a card fingerprint and return a
reusable token.

---

## Scope

**In scope:**
- `POST /payment/v1/cards` endpoint
- Card fingerprint deduplication
- Token return on successful save
- Expiry validation at save time
- No raw card data in logs

**Out of scope:**
- Card retrieval / deletion
- Multi-card UI
- PCI raw storage
- Web / mobile UI changes
- Token refresh (M2 separate PRD)

---

## User Stories

### US-001 — Customer saves a payment method
As a **customer**, I want to save my payment method so I can complete future checkouts
without re-entering card details.
- **Owner:** Harish Kumar
- **Team:** Driver Squad

### US-002 — Invalid card is rejected at save time
As a **customer**, I want invalid or expired cards to be rejected immediately so I am not
surprised with a failure at checkout.
- **Owner:** Harish Kumar
- **Team:** Risk Squad

### US-003 — Duplicate card is not stored twice
As a **customer**, I want the system to detect if I try to save the same card twice so my
saved card list doesn't contain duplicates.
- **Owner:** Harish Kumar
- **Team:** Driver Squad

## Requirements

### REQ-001 (US-001) — Happy-path card save
**Business requirement:** Customer must be able to save a valid card and receive a reusable token.
**Product requirement:** `POST /payment/v1/cards` with a valid `CardDto` returns HTTP 200 with a non-null token.

### REQ-002 (US-001) — All required fields must be present
**Business requirement:** All card fields must be present before the card is saved.
**Product requirement:** `cardNumber`, `expiryMonth`, `expiryYear`, `cvv` are required; any missing field returns HTTP 400 with a JSON error body identifying the missing field.

### REQ-003 (US-003) — Duplicate card is rejected
**Business requirement:** The same card must not be stored more than once for the same customer.
**Product requirement:** If the card fingerprint already exists for this customer, `POST /payment/v1/cards` returns HTTP 409 with error code `DUPLICATE_CARD`.

### REQ-004 (US-002) — Expired card is rejected
**Business requirement:** Cards with a past expiry date must be rejected at save time.
**Product requirement:** If `expiryYear < currentYear`, or `expiryYear == currentYear` and `expiryMonth < currentMonth`, the API returns HTTP 400 with error code `INVALID_EXPIRY`.

### REQ-005 (US-001) — No raw card data in logs
**Business requirement:** PCI-DSS requires that raw card numbers and CVV values are never written to application logs.
**Product requirement:** At no log level (DEBUG, INFO, WARN, ERROR) may `cardNumber` or `cvv` appear in plaintext in application logs.

## Acceptance Criteria

### AC-001 (REQ-001, US-001)
GIVEN a verified customer with a valid Bearer token
WHEN `POST /payment/v1/cards` is called with a complete valid `CardDto`
THEN response is HTTP 200 with body `{"token": "<non-null string>"}`.

### AC-002 (REQ-002, US-001)
GIVEN a `CardDto` with `cardNumber` omitted
WHEN `POST /payment/v1/cards` is called
THEN response is HTTP 400 with body `{"error": "MISSING_FIELD", "field": "cardNumber"}`.

### AC-003 (REQ-003, US-003)
GIVEN a customer who has already saved the same card
WHEN `POST /payment/v1/cards` is called with the same card details
THEN response is HTTP 409 with body `{"error": "DUPLICATE_CARD"}`.

### AC-004 (REQ-004, US-002)
GIVEN a `CardDto` where `expiryYear < currentYear`
WHEN `POST /payment/v1/cards` is called
THEN response is HTTP 400 with body `{"error": "INVALID_EXPIRY"}`.

### AC-005 (REQ-004, US-002)
GIVEN a `CardDto` where `expiryYear == currentYear` AND `expiryMonth < currentMonth`
WHEN `POST /payment/v1/cards` is called
THEN response is HTTP 400 with body `{"error": "INVALID_EXPIRY"}`.

### AC-006 (REQ-005, US-001)
GIVEN any request to `POST /payment/v1/cards`
WHEN the request is processed (success or failure)
THEN no `cardNumber` or `cvv` value appears in application logs at any log level.

## Boundary Values & Thresholds

- `cardNumber`: 13–19 digits, Luhn-valid
- `expiryMonth`: 1–12
- `expiryYear`: 4-digit year
- `cvv`: 3–4 digits
- `holderName`: max 50 characters (optional)
- p95 latency target: 300 ms

---

## Error Codes (expected from API)

| Error Code          | HTTP Status | Trigger |
|---|---|---|
| `MISSING_FIELD`     | 400         | Any required field absent |
| `INVALID_EXPIRY`    | 400         | Card expiry date is in the past |
| `DUPLICATE_CARD`    | 409         | Same fingerprint already saved for customer |
| `SERVICE_UNAVAILABLE` | 503       | Vault service down or timed out |
